# Архитектура программы

Кадровые документы шести видов передают данные в единое событие. При проведении правила определяют группу адресатов, шаблон и почтовый профиль. Адрес, тема и текст сохраняются в задании до передачи. Событие и задания создаются в транзакции проведения.

| Модуль | Ответственность |
|---|---|
| VKRHR | Преобразование специализированного документа в кадровое событие |
| VKRRules | Выбор правила, проверка адресов, заполнение шаблона |
| VKROutbox | Очередь, захват задания и история попыток |
| VKRMail | Сетевой SMTP-сеанс |
| VKROperator | Решение по результату с неизвестным исходом |
| VKRJobs | Запуск очередного цикла |

Сетевой вызов выполняется вне транзакции проведения. Захват ограничен 300 секундами, результат сверяется по токену. После начала передачи отсутствие подтверждения приводит к неизвестному результату и требует решения оператора. Повторное проведение без изменения содержания не создаёт новое письмо.

Пять отчётов СКД используют кадровые события, подтверждённые отправки и историю ошибок. Подразделение уведомления сохраняется на момент подготовки. Права руководителя ограничивают кадровые записи его назначением; без назначения кадровые данные недоступны.

Рабочий стенд использует локальный SMTP и один сеанс учебной платформы. Адаптер типовой ЗУП, внешняя защищённая почта и многопользовательские испытания требуют отдельной реализации и проверки.
