# Средства воспроизведения

build_test_source.py создаёт отдельную копию source с VKRTestDriver и заменой модуля запуска управляемого приложения. Рабочую конфигурацию он не изменяет. Пример: python build_test_source.py --source ../../source --output C:/VKR12_Acceptance_Source.

Загрузить эту копию только в отдельную тестовую базу через Конфигуратор. Сценарий запускается тонким клиентом с /C "VKRTEST|имя_сценария|C:/VKR12_Test/result.json". Возможные сценарии перечислены в процедуре Прогнать файла VKRTestDriver.bsl. JSON содержит версию, пользователя, фактическое время и результат.

SMTP-приёмник с разрывом соединения используется вместо Mailpit на локальном порту 1025. На время этого теста Mailpit должен быть закрыт. Перед запуском передачи дождаться файла READY.txt. Для воспроизведения предназначена отдельная копия; полный сценарий не запускается поверх итоговой базы Accepted.

## Повторение полного сценария

Для средств из этой папки нужен Python 3. Пользовательский показ через DT и CMD из docs/QUICK_START.md Python не требует.

1. В новой базе загрузить копию исходников, созданную build_test_source.py, проверить модули и обновить конфигурацию базы.
2. Выполнить `setup` под администратором. Он дважды вызывает создание учебного набора и создаёт пользователей. Ожидаются 10 сотрудников, 60 событий и 120 заданий. Далее выполнить `repost`.
3. Закрыть Mailpit. Из этой папки запустить `python smtp_disconnect_probe.py --evidence C:/VKR12_Test/smtp_disconnect --count 10`. Дождаться C:/VKR12_Test/smtp_disconnect/READY.txt.
4. Выполнить `enable`, затем два отдельных `cycle`. Каждый цикл передаёт до пяти заданий. Ожидаются 10 Unknown и 110 Prepared. Приёмник завершится после десяти сообщений; сохранить его EML и JSON.
5. Выполнить `disable`. Сверить десять сохранённых сообщений и журнал приёмника. Выполнить `batch_retry`: он создаёт десять документов решения и повторно проводит каждый для проверки отсутствия дублирующего решения.
6. Запустить пустой Mailpit через RUN_NEW_MAILPIT.cmd. Выполнить `enable`, `batch_send`, `disable`. Ожидаются 120 Sent, 130 попыток, 10 ошибок в истории и 10 решений. В Mailpit должно быть 120 писем.
7. Выполнить `batch_workflow`, затем `coverage` и `reports`. Ожидаются 10 завершённых процессов, 50 выполненных задач, от десяти элементов каждого справочника и документов каждого вида.
8. Под администратором выполнить `rls_setup`; затем последовательно запускать `rls_read` под vkr_RukovoditelPodrazdeleniya, vkr_Manager_B и vkr_Manager_None. Ожидаются 6/12, 6/12 и 0/0 событий/уведомлений. Поля с запретом изменения параметра сеанса и неограниченного чтения должны подтверждать отказ.

Пример запуска одного сценария из командной строки Windows; путь базы и имя результата заменить своими:

```bat
"C:\Program Files (x86)\1cv8t\8.3.27.1508\bin\1cv8ct.exe" ENTERPRISE /F "C:\VKR12_Acceptance" /N "vkr_Administrator" /C "VKRTEST|snapshot|C:/VKR12_Test/snapshot.json"
```

Папка для JSON должна существовать. Каждый запуск клиента завершается после сценария; учебная платформа допускает один сеанс базы. В первом пустом запуске `setup` используйте созданного в Конфигураторе администратора либо вход пустой базы без `/N`; тестовые входы появятся после setup.

`batch_workflow` создаёт новые процессы при каждом запуске, поэтому повторяется на новой копии. `change`, `unpost`, `workflow_start`, `workflow_step` и другие диагностические сценарии изменяют тестовое состояние: для них нужна самостоятельная копия. Поле `ok` означает успешное выполнение конкретного сценария; числовые итоги из JSON дополнительно сопоставляются с таблицей приёмки.
